# Diagnosis and Strategy

Use this reference to locate the binding constraint, choose a coherent approach, prioritize work, and convert uncertainty into a staged roadmap.

## Contents

1. Define the system
2. Diagnose performance
3. Choose the constraint
4. Generate strategic options

7. Build the roadmap
8. Stress-test the choice

## 1. Define the system

Map the business model before applying funnel language:

| Model | Critical path |
| --- | --- |
| Self-serve product | Discover -> evaluate -> start -> reach value -> pay -> retain -> expand |
| Sales-led B2B | Target -> engage -> qualify -> evaluate -> close -> adopt -> renew/expand |
| Ecommerce | Discover -> product view -> cart -> purchase -> repeat -> advocate |
| Marketplace | Acquire both sides -> match -> transact -> repeat -> balance liquidity |
| Service business | Discover/refer -> qualify -> trust -> proposal -> close -> deliver -> refer |
| Media/community | Discover -> consume -> return -> subscribe/join -> participate -> monetize |
| Nonprofit/public program | Reach -> understand -> trust -> enroll/act -> complete -> sustain |

Modify the path to match reality. Identify the customer, user, payer, beneficiary, channel partner, and sales or service capacity.

## 2. Diagnose performance

Start with counts and defined rates over a stated window. Segment when aggregate averages hide different behaviors. Trace:

```text
eligible -> reached -> engaged -> qualified -> acted -> succeeded
-> retained -> expanded/referred
```

At each transition ask:

- Is the denominator valid?
- Did volume or rate change?
- Did audience mix, offer, price, season, product, channel, or tracking change?
- Is the observed loss economically material?
- Is the problem acquisition quality rather than downstream conversion?
- Does the organization have capacity to serve more demand?

For weak performance, list at least two rival explanations. Example: low trial conversion might reflect poor onboarding, low-intent acquisition, a broken event, weak product value, price friction, or insufficient time in cohort.

## 3. Choose the constraint

Rank suspected constraints by:

- evidence strength;
- magnitude of outcome blocked;
- causal proximity;
- ability to influence;
- time to learn;
- downstream leverage;
- downside of being wrong.

State the diagnosis:

```text
The primary constraint appears to be [constraint] because [evidence].
Confidence is [low/medium/high].
The strongest alternative explanations are [rivals].
We would change this view if [disconfirming evidence].
```

Do not automatically choose the lowest conversion rate. Some transitions are naturally selective; some high rates mask poor volume or quality.

## 4. Generate strategic options

Create options at the approach level before tactics. Useful patterns include:

- narrow to a higher-urgency segment;
- clarify or reframe the category and promise;
- strengthen proof and risk reversal;
- change the offer, packaging, trial, or sales step;
- capture existing demand more effectively;
- create demand through education, community, or category narratives;
- reduce journey friction or time to value;
- improve activation, retention, or expansion before adding acquisition;
- use partners, customers, product mechanics, or distribution advantages;
- deepen one proven engine before adding channels;
- run a bounded discovery program when evidence is insufficient.

Each option must say who it serves, which constraint it attacks, why it might work, what it requires, when it can show a signal, and what it displaces.

## 5. Prioritize without false precision

Use ordinal ratings such as low/medium/high unless credible numeric inputs exist. Compare:

| Option | Constraint fit | Expected impact | Evidence/confidence | Time to signal | Effort/capacity | Reversibility | Compounding value | Key risk |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |

Apply these gates:

1. Reject options that do not address the diagnosed constraint.
2. Reject options that violate trust, consent, policy, brand, or legal requirements.
3. Reject options the team cannot execute or follow up on.
4. Prefer options that create valuable learning even when they fail.
5. Prefer a balanced portfolio: repair, core engine, and one or two bounded experiments.

Do not hide judgment behind a made-up composite score. Explain decisive tradeoffs.

## 6. Plan capacity and budget

Estimate full cost, not media spend alone:

- internal time and opportunity cost;
- creative, content, engineering, data, sales, and service work;
- tools, vendors, contractors, media, incentives, and fulfillment;
- review, localization, accessibility, compliance, and maintenance;
- lead follow-up and customer-success capacity.

## 7. Build the roadmap

Plan in dependency order:

- **Now:** unblock measurement, audience, offer, proof, or journey issues.
- **Next:** prove the primary strategic premise with a credible minimum.
- **Later:** operationalize the engine and supporting channels.
- **Conditional:** scale or diversify only if named evidence appears.

Every roadmap item needs an owner, output, dependency, checkpoint, metric, assumption, and decision rule. Keep later dates and targets coarse when uncertainty is high.

Include:

- a not-now list with reasons;
- decisions only the user or stakeholder can make;
- bottlenecks and critical path;
- review cadence;
- failure recovery and fallback options.

## 8. Stress-test the choice

Before finalizing, ask:

- What must be true for this strategy to work?
- Which assumption has the highest expected regret?
- What does the plan accidentally optimize at the customer's expense?
- What happens if volume doubles?
- What happens if results are half the base scenario?
- Could seasonality, selection bias, or attribution create a false win?
- Does the engine produce a durable asset, relationship, data advantage, or learning?
- Which plausible alternative strategy did we reject, and why?

Revise if the plan depends on multiple untested assumptions succeeding at once.
